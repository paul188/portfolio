## Overview

NeuroDaRe (GesundheitsDAtentreuhand-REallabor) is a funded research prototype for a healthcare data trust: an intermediary that lets medical data providers and researchers exchange sensitive radiological data without direct access to each other's systems. Providers upload studies in DICOM format, data users request access, and the trust validates and pseudonymises each study before brokering the exchange.

The design is defence-in-depth: each layer from the network edge down to the kernel is guarded on its own, so a single misconfiguration cannot open the whole system. Original patient identifiers (PHI) live in one isolated database, and centralised logging provides the audit trail. The platform runs as 17 Docker containers behind a single `make up-build` entrypoint.

> **Note:** the deployment at neurodare.org is reachable only by vetted medical partners over a WireGuard VPN, so it will not open in a normal browser. The source code is private.

## 2. Service Architecture

**17 Docker containers** run on a shared bridge network. All external traffic enters through nginx, which terminates TLS. No application container is directly exposed to the internet. The diagram at the top of the page shows the full service map.

```
Browser → nginx (:443)
              ├─ /api/*    → FastAPI backend
              ├─ /auth/*   → Keycloak
              └─ /*        → Vue.js SPA
```

## 3. DICOM Upload Pipeline

Each upload runs through a six-step background pipeline. Any failure aborts the session and notifies the provider.

<ClickableImage src="/images/projects/neurodare-dicom-pipeline.png" alt="NeuroDaRe DICOM upload pipeline — validation, virus scan, pseudonymisation, Orthanc ingestion" />

1. **Upload**: files land in a temporary session directory.
2. **Validation**: pydicom-validator rejects every non-DICOM file.
3. **Virus scan**: ClamAV scans every file.
4. **Pseudonymisation**: idiscore replaces all tags that carry patient identifiers with `ANON_XXXXXXXX` values. The mapping goes to the PHI database, the only place that keeps original identifiers (see §5).
5. **Storage**: Orthanc, the DICOM server, writes the pixel data to the S3 object store and indexes the study.
6. **Metadata**: a dataset record makes the study discoverable to data users.

## 4. Authentication Flow

Keycloak 26 is the OIDC provider. FastAPI acts as a confidential OAuth2 client and never handles passwords.

<ClickableImage src="/images/projects/neurodare-auth-flow.png" alt="NeuroDaRe OIDC authentication flow — Keycloak code exchange via FastAPI" />

Login uses the OIDC authorisation code exchange with PKCE, plus an emailed one-time code where 2FA is enrolled. FastAPI stores the session in Redis and redirects each user to the dashboard for their role. Session cookies are `HttpOnly`, `Secure`, and `SameSite=Lax`. CSRF tokens are signed with a separate secret key.
